# Create Video Kit

Create a separate reusable workspace; never modify source references in place
or render an episode unless the user separately requests one. The kit returns
as an exact root to Create Video or Edit Video Project.

## Pipeline

```text
Reference intake → evidence-based kit brief → user confirmation →
kind-specific authoring → validate package → [preview] → hand back exact root
```

### 1. Intake

Read the supplied source project, reference video/stills, brand manual, scene
code, audio, and assets that can establish the requested reusable rules.
Analyze representative moments, not every frame by default. Record what is
directly observable separately from inferred palette, timing, easing, camera,
and asset ownership. Inventory all asset rights and attribution.

### 2. Select one kit kind

Dispatch to exactly one Kind from `routing.md`: Brand, Motion Style, Scene
System, or Show Package. Ask one discriminator only if the stable reusable
payload is unclear. A user may provide exact desired kind; honor it.

### 3. Propose the kit brief

Present one coherent proposal with provenance labels `[fact]`, `[decision]`,
`[suggested]`, and `[derived]`. Include the intended reusable scope, confirmed
constraints, extracted rules, assets to include/exclude, unsupported
inferences, and exact output workspace. Wait for explicit correction or
acceptance before writing final kit artifacts. Explicit delegation permits the
agent to decide and document why.

### 4. Author and validate

Write `kit.md` with only the selected kind's schema, source/provenance notes,
and portable rules. Copy only approved reusable assets. Scene System and Show
Package also include tested scene interfaces and an ordered example roster;
Brand and Motion Style do not acquire an episode roster. Validate all local
references, licensing notes, dimensions, required code entrypoints, and sample
scene rendering.

Provide a browser preview or contact sheet for authored scenes when available.
Report actual workspace root, what is reusable, what remains project-specific,
and known compatibility boundaries. Do not register a library entry unless
the user explicitly asked for it and a registry is part of the target project.
